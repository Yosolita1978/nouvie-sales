### Sistema de reportes del histórico de ventas (nuevo)
Objetivo de negocio: a partir del archivo viejo de ventas, encontrar clientes que **no compran hace +6 meses** para contactarlos con un mensaje personalizado, y ver mejores/peores productos y clientes por año. Fuente: `nouvie-historic/VENTAS NOUVIE - VENTAS (1).csv` (357 ventas, ~abril 2024 → marzo 2026).

**Tablas aisladas (schema)** — `prisma/schema.prisma`
- `HistoricSale` + `HistoricSaleItem` (ventas y líneas de producto parseadas) y `HistoricProductMapping` (mapeo manual). **Sin llaves foráneas a customers/products/orders**: nombres de cliente/producto son strings. Así el histórico no toca los datos vivos (sin duplicados ni conflictos).
- Este DB **no tiene migración base** (se creó con `db push`; la única migración es un ALTER a mano), así que `prisma migrate dev` falla con P3006. **Se usa `npx prisma db push`** para cambios de esquema aquí.

**Script de importación** — `scripts/import-historic.ts`
- Dry run por defecto; `--commit` escribe (idempotente: borra y reconstruye las 2 tablas del histórico). Nunca toca tablas vivas.
- Infiere el **año** por secuencia (el CSV no tiene columna de año; usa marcadores `2025`/`enero 2026` y el salto dic→enero). Normaliza **montos** en formatos mezclados US (`$78,000.00`) y CO (`$221.700,00`). Parsea el texto libre de `PEDIDO` a productos canónicos (colores → productos de Hogar confirmados por el cliente; kits `de/por/x 5` se expanden; escentes capilares como "Shampoo Melón" quedan como su propio nombre). Lo que no reconoce queda como `UNMAPPED: …` + flag (nada se pierde).
- Cobertura: **~95%** (852 ítems mapeados / 45 sin mapear, luego 34 grupos distintos tras normalizar la clave).
- Genera `scripts/output/historic-unmapped-review.csv` para revisión.

**Página de reportes** — `app/(dashboard)/historico/page.tsx` (server component, solo lee tablas del histórico) + link "Histórico" en `components/layout/Sidebar.tsx`
- Secciones: resumen por año, mejor/peor producto por año, mejores clientes por año, **clientes inactivos +6 meses** (lista de contacto, 156), clientes de una sola compra (119), ⚠️ montos a revisar, cobertura.

**UI de "sin clasificar" / overmap** — `app/(dashboard)/historico/mapeo/page.tsx` + `MapeoTable.tsx` + `app/api/historico/mapping/route.ts`
- El cliente asigna un producto a cada texto no reconocido **desde la plataforma** (sin código). Guarda en `historic_product_mappings`; la página de reportes lo aplica en vivo (`resolveProduct`).
- Cada fila muestra un **ejemplo del pedido original** (con número de línea) para dar contexto, y un **combobox** (input + datalist de ~91 productos): el cliente puede escribir Y elegir de la lista.

## Learned
- El DB (Supabase compartido) **no tiene migración base** → `migrate dev` no sirve; usar `db push`.
- Precios en el DB están **sin IVA**; ×1.19 = precio con IVA de la web. Así se confirmó que "Tratamiento" (admin) = "Kit Completo" (web): $98.151 ×1.19 = $116.800.
- La línea **Revitalizante tiene solo 2 productos** (sin mascarilla) a propósito → su kit es más barato. No es un faltante.
- Bug de cantidad: `"500 ml limpia superficies"` leía cantidad **500** (era volumen, no unidades). `leadingQty` ahora trata un número seguido de unidad (ml/litros) como cantidad 1. Verificar los datos antes de construir reportes encima evitó propagar el error.
- La lista de inactivos **+6 meses se basa solo en el histórico**: un cliente que compró por el sistema vivo en 2026 igual saldría como inactivo. Hay que cruzar con ventas actuales (Fase 3) antes de contactar.
